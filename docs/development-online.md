# 本地开发，线上数据

用户2026-11-13确认：浏览器打开localhost本地页面，改代码后热更新；登录和业务接口使用既有线上服务。不是把线上站点切成开发服务器。

## 当前配置

- 前端：`http://localhost:5173`，Vite仅监听本机，支持原生HMR。
- API：浏览器使用同源`/api`、`/auth`、`/uploads`，Vite转发到`https://shop.yuezo.com`。
- `frontend/.env.development.local`设置`SHOPDESK_API_TARGET=https://shop.yuezo.com`。该文件不提交；未设置时Vite默认代理本地8088，可用于独立本地后端开发。
- 所有环境API地址使用相对路径，避免开发页面绕过代理连接本地账号库。
- 线上站点保留静态发布模式、原登录及原数据库；此前尝试的反向隧道和线上热更新转发已撤回。

## 运行

在项目根目录执行`python3 scripts/dev-online.py start`。`status`检查本地进程，`stop`结束本次脚本创建的进程。也可以直接在frontend运行`npm run dev`。

本地页面与线上页面是不同浏览器来源。首次打开localhost需要用原线上账号正常登录一次，密码校验由线上后端执行，不需要新建或重置本地账号；线上已登录会话保留。浏览器不自动共享两个来源的localStorage。

此模式直接使用线上数据：用户在页面执行的业务写入也会发送至线上。助手验证限于读取、订单同步及界面调整，不擅自发布商品或操作买家。

Vite文件访问限制为frontend，不允许读取backend、环境文件、Git目录或密钥文件。已核对本地API代理健康返回200、后端文件访问返回403。未调整框架或安装新依赖。

已观察用户在Chrome的localhost页面完成线上账号登录：页面返回真实5单订单提醒与11单待履约，上次同步时间位于统一同步按钮旁。后续界面调整默认本地热更新供用户查看，不因修改代码自动发布线上；用户明确要求发布时再执行部署。
