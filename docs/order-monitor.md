# 首页订单履约监控

2026-11-13。本次仅订单监控，不包括库存、评价或自动发货。

## 行为

首页仅保留紧凑订单提醒入口，显示当前账号和顶部店铺范围的预警数量、截止待核对数量、来源与快照时间，不在首页展示订单清单。点击进入订单页“订单提醒”筛选，支持全部店铺或单店铺。具体订单、倒计时及真实平台截止时间均显示在订单列表的“履约状态与截止”列。

订单提醒列表按风险和截止时间排序，分“待准备发货”（AWAITING_SHIPMENT、PARTIALLY_SHIPPING）及“待物流揽收”（AWAITING_COLLECTION）。未支付、暂挂、已取消、运输中及完成订单不纳入本次待办。

进入首页及页面可见时每5分钟调用现有 Partner 订单同步，范围为近90天；首页与订单页每分钟刷新本地监控计算，订单页可见时同样每5分钟同步平台。手动同步按店铺顺序执行，失败店铺单独提示。页面关闭后不运行后台同步，不承诺常驻调度。旧快照仍可查看，每单超过30分钟会标记。

分别使用平台订单 rts_sla_time、tts_sla_time、cancel_order_sla_time。用户已于2026-11-13确认暂定提前24小时（一天）作为处理缓冲。24小时是内部预警窗口，不是平台时限，也不延长平台截止；无截止时间显示待同步，不从下单/支付时间推算。自动取消临近/超时优先，其次阶段截止超时、即将到期、截止未知、未到预警。

订单列表显示阶段、风险、商品及SKU、店铺订单号、阶段截止及剩余时间、自动取消真实截止与剩余时间（若返回），陈旧快照单独提示。首页入口进入已有订单页，带入店铺与提醒筛选。所有展示时间按墨西哥城时区。

监控 GET /api/tiktok/order-monitor，支持 shop_id、stage、page、page_size；订单列表支持 shop_id=ALL 和 needs_attention=true，仍按当前账号隔离；只读取当前账号店铺。平台同步仍由已有 POST /api/tiktok/shops/{shop_id}/orders/sync 执行，只读平台、更新本地，不执行平台发货或其他买家操作。

## 数据与启动

新增 shop_orders 三个可空 INTEGER 列，对应上述平台字段。启动时沿用 migrations.py 幂等补列；旧订单缺值等待再次同步。保留原订单、账号、凭据和业务数据。

开发运行：后端在 backend 目录使用 venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8088；前端在 frontend 目录 npm run dev。本次未修改原 start.sh 的启动方式。

## 官方依据与限制

- [墨西哥履约政策](https://seller-mx.tiktok.com/university/essay?knowledge_id=8357698199193360&lang=es-419)：2026-09-30更新；推荐一工作日准备好、三工作日进入已发货、七工作日自动取消规则，当地时间及节假日适用。英文迟发率段落与SLA表存在2/3工作日差异，因此不把固定天数写入算法。
- [Partner订单流程](https://partner.tiktokshop.com/docv2/page/order-api-overview)：安排发货与物流收件是不同节点。
- 真实授权只读拉取86单，其中11单待物流揽收、5单在24小时内到期，11单均有揽收截止；这只是本次快照，不代表持续实时状态。
- 同步沿用现有近90天创建时间查询。更早的本地订单可能持续显示旧快照提示；跨90天活跃订单的专项刷新尚未实现。
- 已部署到现有线上服务，并在原已登录Chrome会话核对真实列表、空阶段、分页、订单定位跳转。上线前备份了数据库、后端文件、前端资源；原前端基线JS/CSS摘要与线上完全一致，发布仅引入本次监控改动。
- 常用桌面窗口已查看实际截图；1000×680最小窗口尚未完成线上视觉验证，不报告全尺寸验收通过。
- 本地独立账号校验失败不影响线上登录；本次未修改任何账号密码。
