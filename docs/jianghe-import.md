## 必须保留的内容

- 货号：作为来源商品标识，不能因颜色子行重复建SPU。SKC不作为SPU归组依据或要求用户处理，可保留原值作来源追溯。
- 原始商品合成图：保存可用原图及来源，含其中的正/侧/背和其他图内文字信息。先提取实际可见结构与文字，缺失视角不冒充实拍；未来据此制作三视图，此次导入不等于三视图已生成。
- 颜色：使用文字和原图的实际颜色，可能单色或多色；与实际尺码组织SKU。不臆造组合。
- 品名：保留原文，后续用作标题与描述的事实资料。
- 单价：币种MXN，原表为单件价格。套装需保存原单件价、套装件数、计算口径及套装采购价。例如5件装且单件18比索，套装价90比索。件数不明或含义有歧义的不能猜测。
- 最低起订量：本次不作为SKU、销售件数、库存或导入阻塞条件。
- 尺码：保留实际范围和原值，能明确展开时才建立颜色×尺码变体。
- 尺码表：保留中文原始图片、原始数值、单位和测量口径；后续上架另制作西语尺码表，不能丢掉原图或把翻译稿覆盖来源。
- 成分：完整保留原始材质名称与比例，混纺按原文；不能从相似商品套用。
- 产品实拍图：保存该商品的阿里网盘链接；暂不打开、下载或整理网盘图片。
- 保留来源工作表、行号/单元格、采集时间、图文提取结果及冲突，供后续标题、描述、主副图和SKU自动化使用。

## 后续供应商适配原则

供应商可能提供SPU表、SKU列表或其他结构，由助手分析实际资料并映射到系统，不要求供应商统一数据组织方式。归组需有货号、结构等明确依据，不能只凭名称相近合并。未知库存不能用系统默认999冒充供应商现货。
